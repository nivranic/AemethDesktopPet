# ZCode Pet Plugin Implementation Plan

**Goal:** 通过 ZCode 支持的插件入口运行独立 Windows 桌宠，兼容现有 Aemeath Mini V2 素材，并明确区分已验证功能与宿主接入限制。

**Architecture:** 插件负责接收宿主事件和提供控制工具；独立原生窗口负责透明置顶显示、动画、鼠标交互与状态聚合。双方通过限制为当前 Windows 用户的命名管道交换最小状态，不复制聊天内容或依赖 Codex 私有 IPC。

**Tech Stack:** Node.js 内置模块、Windows .NET Framework WinForms/GDI+、现有 V2 atlas。使用本机编译器，无需修改 Codex/ZCode 安装包。

## 决策和备选方案

1. 优先插件与独立窗口：保留宿主升级能力，播放器速度可配置。代价是多一个轻量进程，目前只实现 Windows。
2. 若 ZCode 提供原生 UI 扩展，可直接使用；以实际插件 API 为准。
3. 修改安装包不是本方案：与受管理发行包耦合，也不满足稳定插件交付。

## Task 1: 实现证据

核查当前 Codex 与 ZCode 的版本、包内源码位置、素材协议、任务事件和插件格式。将事实与建议分开记录到 docs/source-analysis.md。不整体解包，不交付产品私有源码。

## Task 2: 原生 Companion

- 创建 native/Companion.cs、native/build.ps1。
- 读取无损 PNG atlas：1536×2288，每格192×208。
- 透明、置顶、不抢焦点、拖动、多屏边界、透明像素鼠标穿透、16方向。
- 默认 idle 使用基础时长，工作状态持续循环；保留57个标准帧和16方向素材。
- 管道输入限长/白名单/当前用户权限，窗口关闭时释放图像、timer及管道。
- 验证编译、动画时序、聚合优先级、输入拒绝和渲染结果。

## Task 3: 插件适配

- 根据源码确认的宿主格式生成清单、工具和可用事件适配。
- Node 桥接仅发送规范化状态与不可逆会话标识，不存储 prompt/tool 参数。
- 不把按需 MCP 调用宣称为自动任务事件；仅为已核实的事件提供自动接入。
- 无路径逃逸、任意执行或远程监听接口；启动/停止仅作用于本插件 companion。

## Task 4: 素材、验证与交付

- 将原 WebP 无损解码为 PNG供原生播放器使用，比较全部 RGBA 像素；附原素材许可和 NOTICE。
- 测试桥接、并发会话、进程退出、插件清单和实际窗口行为；未观察到的宿主联动明确标注。
- 提供插件包、中文安装/卸载说明与源码核查记录。
- 本任务不提交或推送源码，也不更改宿主安装包。
